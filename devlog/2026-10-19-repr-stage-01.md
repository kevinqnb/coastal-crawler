## Session 2026-10-19

### Prompts
Plan and build a stage that uses `scholarlm.RepresentationLM` to collect
Llama-3.1-8B embeddings of the coastal-ecosystem terms from `FILTER_RELEVANCE_PROMPT`
at every occurrence in the relevant papers, integrated with the existing database and
with a clean, memory-efficient on-disk layout. Follow-ups (summarized): store
embeddings under the repo's `data/`; read table-clean text; include irregular plurals,
spelling variants and wetland terms as separate terms; use float32; also collect
layer 0 (token embeddings) as a baseline, which means bumping scholarlm to its latest
commit and fixing table cleaning afterwards; run the DB tests on a throwaway Postgres,
not the live one; commit on a `repr-study` branch and start this devlog.

### Implemented
Adds a `repr` stage that collects `RepresentationLM` term embeddings per paper, run
in-process with no model server. It is tracked in a new `paper_representations` table
(migration `c3d4e5f6a7b8`) keyed on `(paper_id, run_id)`, so it never touches
`papers.status` and can run beside extraction. Per-paper `.npz` shards (one array per
layer) go under `data/representations/<run_id>/`, with an `index.parquet` reconciled
against the database. New entry points: `repr_worker.py`, `repr-seed`/`repr`/
`repr-index` CLI commands, and a `repr` stage in `scripts/run_experiment.py` and
`scripts/submit.sh`. Configs: `configs/repr-terms/coastal-terms-01.txt` and
`configs/2026-10-19-repr-llama31-8b-{smoke,tiny,full}-01.yaml`. Rung 1 (unit tests on
a throwaway Postgres) passed. scholarlm is bumped to the commit with multi-layer
`RepresentationLM`, and the table-clean and extraction adapters were adapted to its
removed `MeasurementLM` table-cleaning API; the smoke, tiny and full runs are covered in
the next session block.
